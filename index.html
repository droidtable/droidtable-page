darktable on your phone.

A touch-friendly Android photo editor built on darktable's own processing engine.

Droidtable does not imitate darktable — it runs it. The original darktable processing modules render your RAW files on the phone, and your edits are stored in the same XMP sidecar files desktop darktable reads and writes. Start an edit on the go, finish it at your desk, or the other way round.

Why Droidtable?

The real engine

No re-implementation of darktable's maths in another language. Droidtable builds libdarktable for Android without GTK and calls the unchanged processing code, so a module behaves the way it does on the desktop.

One edit, two devices

A RAW file opens together with its <name>.xmp sidecar. Saving writes the same format desktop darktable reloads — history, module instances and masks included. No export/import step, no proprietary catalogue.

Made for touch

A new Kotlin and Jetpack Compose interface designed for fingers instead of a mouse: large sliders, tap-to-type values, gestures on the preview and a layout that works on a phone first.

Desktop ↔ phone workflow

  1. Copy or sync your RAW files and their .xmp sidecars to the phone — any folder you can open with Android's file picker works.
  2. Edit in Droidtable. Existing desktop edits are rendered by the same modules; you continue where you left off.
  3. Save. Droidtable writes the sidecar safely (a failed write never damages the old one) in darktable's own XMP format.
  4. Back on the desktop, darktable 5.6.1 or later reloads the sidecar and shows exactly the same history.

Keeping darktable's results

  • Image processing is never changed. The darktable changes only hide desktop GUI code behind a build switch (DARKTABLE_ENGINE_ONLY), split shared headers into core and GUI parts, and fix small differences of Android's C library and compiler.
  • Verified against desktop darktable. The engine-only build is bit-exact with the official desktop release on x86; on the phone's ARM CPU, renders are compared pixel by pixel within a measured tolerance policy.
  • Every change is public. The fork keeps one commit per change on top of the darktable release tag, labelled build:, engine: or android:. Each engine version is tagged droidtable-5.6.2-dd.N and published with its prebuilt package, licenses and corresponding source.
  • Releases, not nightlies. Droidtable follows darktable releases only. A new release is adopted by replaying the fork's commits onto it and re-running the full compatibility suite.

Status & roadmap

  1. Desktop compatibility baseline
    Pinned darktable 5.6.2, reference renders and sidecars produced by desktop darktable.
  2. GTK-free engine with all 93 modules
    Built without the desktop UI, bit-exact with the official desktop build.
  3. Engine on Android
    Cross-compiled for arm64 with the Android NDK, running inside the APK in its own process behind a Binder contract.
  4. App shell & sidecar round-trip
    Open files through the system picker, render previews and full-size images, edit and save XMPs that desktop darktable reloads.
  5. Editor in progress
    Module panels, masks, histogram scopes, history and export are working. Next: parametric masks, before/after view, a generic panel for the remaining modules, "Open with" integration and tablet layouts.
  6. Optimize & release
    Speed and memory tuning, GPU acceleration after CPU correctness, automated round-trip tests and a first public release.

Requirements (current development builds)

  • Android 15 (API level 35) or later.
  • 64-bit ARM device (arm64-v8a).
  • darktable 5.6.1 or later on the desktop to exchange sidecars.
  • RAW formats supported by darktable's 5.6.2 decoders; JPEG and other common formats as well.

FAQ

Is Droidtable an official darktable project?

No. Droidtable is an independent project that builds on darktable's source code under its GPL license. It is not affiliated with or endorsed by the darktable team. Please report Droidtable problems to Droidtable, not to darktable.

Does it give exactly the same result as desktop darktable?

It runs the same processing code. On the same CPU architecture the result is bit-exact; between a desktop x86 CPU and a phone's ARM CPU tiny floating-point differences remain, which are measured and kept within a documented tolerance.

Can I use every darktable module?

The engine contains all 93 processing modules, so every edit made on the desktop is rendered. Editing on the phone needs a touch panel for each module; the list above grows with each release.

Does it have a photo library database like darktable?

No catalogue is needed: the XMP sidecar next to the image is the source of truth, which is what makes moving between desktop and phone simple.

Is GPU (OpenCL) processing used?

Not yet. Correct CPU results come first; GPU acceleration is part of the optimization phase.

Where is the source code?

All darktable changes and the engine packages with their corresponding source are public in the droidtable/darktable fork. The app source will be published together with the first app release.
